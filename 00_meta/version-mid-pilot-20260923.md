## 对抗式审查

这是主任务逐项反证，不是独立研究员审查。检查的问题是：即使方案按计划做完，为什么仍可能写不出好看的比赛？

| 被审查的假设 | 反例或遗漏 | 本轮处理 |
|---|---|---|
| 按版本筛英雄，自然能找到高光 | 强势出装可以是所有职业选手的公共答案，研究正确仍不惊艳 | 分开标注“版本研究成立”和“人物高光成立”；本轮后者为0，不凑数 |
| 新英雄可成为春季职业惊喜 | 獸在7.31上线，7.32才加入队长模式 | 春夏只能研究天梯/非CM玩法；赛事可用另查规则。此限制主仓已有，本次修复的是计划没有落实它 |
| 换位置就是创新 | 光法中单在TI10前已有比赛报道；船长、龙骑等更不能自动算新开发 | 先查历史基线，不安排职业选手因为“居然能中单”而震惊 |
| 7.31是一套固定答案 | 挂件在7.31获得减蓝耗，7.31d又失去；光法、獸在7.31c遭调整 | 结论绑定字母补丁，不以大版本名覆盖数月 |
| 对线克制能传递 | A对B有优势、B对C有优势，不推出A对C有优势；赢线也不保证阵容赢 | 分开记录对线、转线、阵容任务、正常反制；不用静态胜率代替原因 |
| 单人刷得快就是团队方案好 | 刷的是队友需要的野，或经济领先却没人开团/拆塔 | 同时记被替换中单的功能、资源占用、队友配合和目标兑现 |
| 熟悉未来历史可缩短推演 | 作者知道职业答案，角色当时并不知道 | 每个候选写“当时可见线索→待验证判断→可观察反馈”；后来赛事只供作者校准 |
| 多英雄熟练度必须靠堆完整对局 | 现有系统允许普通可重复专项训练；客户端英雄等级也不是能力值 | 不新增训练限制、不虚构几百把背景；能力评分、客户端等级、实际技术分开 |
| 数据库中路标签能直接统计二号位 | 旧语料的`lane_role=2`也会落在辅助身上 | 本轮只摘有选手名和经济/补刀交叉线索的案例，仍保留身份局限；不发中单使用率 |
| 拿到购买日志便知道比赛打法 | 购买不等于同时在六格生效，也不证明玩家为何购买 | 保留日志事实；背包、出售、交战状态不由购买次数补齐 |
| 多看一些就一定能找到 | 已反复扩展英雄和筛选规则，却未提高场景质量 | 首轮只做3张研究卡、2个对抗任务；卡住记录缺口，不继续扩英雄 |
| 所有结论最终都要保留 | 系统性研究也可能只能给常识和版本背景 | 普通处理归入背景；明确额外收益和对抗空间后才升级为情节候选 |

另有数据风险：既有语料某些`*_utc`/`*_beijing`派生字符串带本地偏移，字段名不足以保证时区。本轮时间直接从Unix秒转UTC，不批量重写旧语料；后续精确历史时间必须重新转换。官方补丁接口的`patch_timestamp`同样不是已验证的客户端切换时刻。
